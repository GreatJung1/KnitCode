# KnitCode
### Python AST-based Static Call Graph Analyzer

Python 코드를 실행하지 않고 **AST(Abstract Syntax Tree)를 분석하여 함수 및 메서드 간 호출 관계를 추적하는 정적 호출 그래프 분석기**입니다.

현재 **Prototype 2(v2.4)**까지 개발했으며, 실제 오픈소스 프로젝트 3개를 대상으로 분석 및 검증을 진행했습니다.

---

## 1. 프로젝트 목표

Python 프로젝트의 소스코드를 정적으로 분석하여 **어떤 함수가 어떤 함수나 메서드를 호출하는지 파악하고 이를 그래프로 표현하는 것**을 목표로 합니다.

주요 목표는 다음과 같습니다.

- AST 기반 함수·클래스·메서드 등 심볼 추출
- 함수 및 메서드 간 호출 관계(Call Graph) 생성
- 객체 생성, 변수 재할당, 상속, import 등을 고려한 호출 대상 추론
- 분석하지 못한 호출의 원인 분류 및 추론 근거 기록
- JSON/CSV 및 HTML 형태의 분석 결과 제공

전체적인 분석 과정은 다음과 같습니다.

`Python 소스 → AST 분석 → 심볼 추출 → 호출 대상 추론 → 호출 그래프 생성 → 미해결 호출 분류 → 결과 출력`

## 2. Prototype 1 (v1)

**기본적인 AST 기반 정적 호출 그래프 구현**

Python 소스코드에서 함수, 클래스, 메서드 및 호출 정보를 추출하고, 정적으로 확인할 수 있는 호출 관계를 연결하는 초기 프로토타입을 개발했습니다.

- Python AST 파싱 및 심볼 수집
- 함수·메서드 호출 관계 분석
- 객체 생성 및 기본적인 메서드 호출 연결
- 호출 그래프 및 분석 결과 출력

**한계점**

조건문 내부에서 발생하는 변수 대입이나 객체 생성은 안전한 추론이 어렵다고 판단하여 일부 연결을 제외했습니다.

예를 들어 `if` 블록 내부에서 객체를 생성한 뒤 메서드를 호출하는 경우에도 호출 관계를 놓치는 문제가 있었습니다.

이러한 한계를 개선하기 위해 Prototype 2 개발을 진행했습니다.

## 3. Prototype 2 (v2.0 ~ v2.4)

**호출 추론 기능 확장 및 분석 결과의 신뢰성 개선**

### ① 제어 흐름 기반 호출 분석
- `if/else` 분기와 변수 재할당에 따른 호출 관계 추적
- 복수의 호출 대상 및 조건부 호출 가능성 분석
- 불확실한 호출은 `MAY_CALL`로 표시

### ② 미해결 호출 분류
- 연결하지 못한 호출을 10개 범주로 세분화
- 내장 함수, 외부 라이브러리, 간접 호출, 객체 타입 불명 등 원인 구분
- 분류 근거와 후보를 JSON/CSV/HTML로 출력

### ③ 모듈·컬렉션 간접 호출 분석
- 함수 외부(모듈 수준)에서 발생하는 호출 분석
- 리스트·딕셔너리 등에 저장된 클래스 후보 추적
- 복수 호출 후보를 보수적으로 기록

### ④ Import 및 그래프 정확성 개선
- 상대 import, 별칭 import 및 재수출 경로 추적
- `@overload`와 실제 구현 함수 구분
- 중복된 심볼·간선 제거 및 잘못된 외부 호출 연결 방지

### ⑤ 호출 상태 및 추론 근거 구분
- `RESOLVED_INTERNAL`: 프로젝트 내부 호출로 연결
- `KNOWN_NON_INTERNAL`: 내부 호출이 아닌 것으로 판단
- `UNKNOWN`: 정적 근거가 부족한 호출
- 각 호출의 판단 근거와 불확실성 기록

### ⑥ 타입 힌트 기반 호출 추론 (v2.4)
- 매개변수 타입 힌트를 활용한 메서드 호출 연결
- 클래스 별칭, 상속 관계 및 변수 재할당 고려
- 타입 힌트 기반 호출을 `MAY_CALL`로 표시

## 4. 테스트에 사용한 GitHub 프로젝트

실제 오픈소스 Python 프로젝트를 대상으로 분석 기능을 검증했습니다.

**1. [Sublist3r](https://github.com/aboul3la/Sublist3r)**

서브도메인 탐색 도구로, 조건문 내부 객체 생성, 클래스 간 호출, 컬렉션을 활용한 간접 호출 분석을 검증하는 데 활용했습니다.

**2. [Requests](https://github.com/psf/requests)**

Python HTTP 라이브러리로, 모듈 간 import, 재수출 경로, 클래스 상속 및 객체 메서드 호출 분석을 검증했습니다.

**3. [Click](https://github.com/pallets/click)**

Python CLI 프레임워크로, 클래스 간 호출 관계와 매개변수 타입 힌트를 활용한 메서드 호출 추론을 검증했습니다.

분석 시 Requests와 Click은 각각 `src`를 분석 루트로 사용했고, Sublist3r는 프로젝트 소스 루트를 사용했습니다.

## 5. 분석 및 검증 결과

### 5.1 전체 프로젝트 분석

| 항목 | Sublist3r | Requests | Click | 합계 |
|---|---:|---:|---:|---:|
| Python 파일 | 4 | 19 | 17 | 40 |
| 전체 호출 | 514 | 986 | 2,054 | **3,554** |
| 내부 호출 연결 | 124 | 286 | 625 | **1,035** |
| 비내부 호출 | 181 | 416 | 782 | **1,379** |
| 미확정 호출 | 209 | 284 | 647 | **1,140** |
| 파싱 오류 | 0 | 0 | 0 | **0** |

총 **3,554개 호출**을 분석했으며, 내부 호출 연결에 실패한 2,519개를 비내부 호출 1,379개와 미확정 호출 1,140개로 구분했습니다.

### 5.2 버전별 개선 결과

매개변수 타입 힌트 기반 추론 기능의 효과를 확인하기 위해 v2.3.1과 v2.4의 내부 호출 연결 수를 비교했습니다.

| 프로젝트 | v2.3.1 | v2.4 | 추가 연결 |
|---|---:|---:|---:|
| Sublist3r | 124 | 124 | 0 |
| Requests | 280 | 286 | +6 |
| Click | 582 | 625 | +43 |
| **합계** | **986** | **1,035** | **+49** |

v2.4에서 **총 49개 내부 호출을 추가 연결**했으며, 해당 신규 호출 49개는 원본 소스코드의 타입 선언, 상속 관계, 실제 메서드 정의와 대조하여 정적 추론 근거를 검토했습니다.

### 5.3 검증 방법

검증 과정은 다음과 같습니다.

- 단위 테스트: 총 93개 테스트 통과
- 그래프 정합성 검사: 16개 항목
- 호출 상태 검사: 10개 항목
- 타입 힌트 추론 검사: 4개 항목
- AST 호출·심볼 위치 일치 여부 확인
- 이전 버전과의 호출 연결 변화 비교
- 실제 원본 소스코드를 활용한 Ground Truth 평가

### 5.4 Ground Truth 기반 정확도 평가

3개 프로젝트에서 총 **294개 호출을 선정**하여 원본 코드와 대조했습니다.

| 항목 | 결과 |
|---|---:|
| 검증 호출 | 294 |
| TP | 103 |
| FP | 0 |
| FN | 29 |
| TN | 160 |
| 판정 보류 | 2 |

판정 가능한 292개 표본 기준:

- **Precision:** 100%
- **Recall:** 78.0%
- **F1-score:** 87.7%

검증 표본에서 잘못된 내부 연결은 발견되지 않았지만, **실제 내부 호출을 연결하지 못한 사례 29개**를 확인했습니다.

단, 해당 평가에는 미해결 가능성이 높은 호출을 의도적으로 선정한 사례도 포함되어 있어, 위 수치를 전체 프로젝트의 일반적인 정확도로 해석할 수는 없습니다.

## 6. 실행 방법

**환경**
- Python 3.10 이상
- Windows PowerShell 기준
- Python 표준 라이브러리만 사용

프로젝트 소스코드를 분석하려면 다음 명령어를 실행합니다.

```powershell
python main.py <분석할_프로젝트_경로> --output-dir output
```

자동 테스트:

```powershell
python -m unittest discover -s tests -v
```

정합성 검증:

```powershell
python verify_v24.py --graph output\graph_result.json --symbols output\symbol_result.json --repo <분석할_프로젝트_경로>
```

HTML 결과 보고서:

```powershell
start output\report.html
```

**주요 출력 파일**

| 파일 | 내용 |
|---|---|
| `ast_result.json` | AST 분석 결과 |
| `symbol_result.json` | 함수·클래스 등 심볼 정보 |
| `graph_result.json` | 호출 그래프 및 간선 |
| `call_statuses.json/csv` | 전체 호출 상태 및 근거 |
| `unresolved_classification.json/csv` | 미해결 호출 원인 분류 |
| `report.html` | 시각적 분석 보고서 |

## 7. 현재 한계점

Python의 동적 특성으로 인해 모든 호출 관계를 정적으로 확정할 수는 없습니다.

현재 확인된 주요 한계는 다음과 같습니다.

- 함수 반환값의 객체 타입 추적 부족
- `self.obj.method()`와 같은 연속 필드 접근
- 컬렉션에서 꺼낸 객체의 타입 추론
- 복잡한 함수 간 인자 전달 및 데이터 흐름
- 복합 타입 힌트와 다형성 호출
- 동적 import, reflection, monkey patch 등

불확실한 호출 관계는 가능한 한 임의로 확정하지 않고 `MAY_CALL` 또는 `UNKNOWN`으로 기록합니다.

## 8. 향후 개발 목표 — Prototype 3

Prototype 3에서는 **내부 호출 누락(FN)을 줄이면서 잘못된 연결(FP)을 최소화하는 것**을 목표로 합니다.

**주요 개발 계획**

1. **객체 타입 추적 강화**  
   변수 대입 및 객체 참조를 통한 타입 추론 확대

2. **함수 반환 타입 분석**  
   함수가 반환한 객체의 타입을 추적해 이후 메서드 호출 연결

3. **객체 필드 분석**  
   `self.obj.method()` 형태의 호출 추론 확대

4. **복합 타입 및 간접 호출 분석 개선**  
   `Optional`, `Union`, 컬렉션 내부 객체 등 처리 범위 확대

5. **정량 평가 고도화**  
   기존 FN 사례 재검증, 회귀 테스트, 독립 평가 표본 확대 및 Precision/Recall/F1 비교

모든 동적 호출을 무리하게 해석하기보다, **정적 근거가 충분한 호출부터 단계적으로 지원 범위를 확대**할 예정입니다.
